# Промпт для продолжения работы над Radio 345

Ниже — готовый контекст и задача для следующей сессии. Факты и результаты
зафиксированы 15.11.2026; фактический архив с тех пор может пополняться.

---

Ты работаешь над Radio 345 в `/Users/jackrv/Documents/Projects/radio`.
Главная задача — повысить точность распознавания слов, фраз и номеров в
шумном радиообмене. Пользователь прослушивает WAV и сохраняет точный эталон.
Приоритет следующего этапа — использование повторяющихся речевых конструкций
и допустимых сокращений при распознавании. Роли «кому / от кого» сейчас вторичны.

## Текущее устройство и ограничения

- Сейчас проект работает на Mac через MLX. Whisper:
  `mlx-community/whisper-large-v3-mlx` (до 17.11.2026 — `whisper-large-v3-turbo`); текстовый корректор:
  `mlx-community/Qwen2.5-3B-Instruct-4bit`.
- В рабочем Whisper язык `uk`, prompt из имён словарей,
  `temperature=(0.0,0.2,0.4)`, `condition_on_previous_text=False`,
  `no_speech_threshold=0.6`, `logprob_threshold=-1.0`,
  `compression_ratio_threshold=2.4`.
- PCM16, mono, 16 кГц, gain 1, MIN_RMS 0.02, нормализация пика до 0.9.
  WebRTC VAD: 30-мс кадры, уровень 2, preroll 500 мс, минимум речи 500 мс,
  завершающая тишина 600 мс, максимум сегмента 20 с.
- Установленный MLX Whisper не реализует beam search. Не добавляй beam_size
  и не обещай N-best кандидаты без проверки поддерживаемого движка.
- Целевая платформа — Raspberry Pi 5, 4 ГБ RAM, интернет будет; ускоритель
  не выбран. Нужна проверка Whisper base/small через whisper.cpp и, возможно,
  Parakeet v3 INT8 через sherpa-onnx. Скорость на Pi пока не измерена.
  Дообучение выполняется на отдельном компьютере, готовые веса — на Pi.
  MLX-реализацию при переезде придётся заменить.

## Что уже сделано

1. Ранее реализованы локальный аудиоархив, проигрывание WAV, независимые
   эталоны, типы speech/noise/notification/room/unclear, роли, отметка нескольких
   передач, метрики и компактный интерфейс разметки. При проигрывании через
   колонки есть удержание микрофона для защиты от повторной записи звука.
2. Исправлено пополнение очередей A–D. Раньше UI читал один файл фиксированных
   ID, и после разметки 179 записей казалось, что больше нечего проверять.
   Теперь очереди вычисляются из SQLite и пополняются новыми записями.
   A — ready/empty_text/blacklist; B — low_rms −36…−34 dBFS;
   C — low_rms ниже −36 dBFS; D — vad_short с речью от 300 мс.
   Лимиты 15/10/20 в UI убраны; старые экспериментальные выборки сохранены.
3. Счётчики очередей обновляются примерно раз в 10 с. Карточки загружаются
   кнопкой «Оновити записи», чтобы фоновые обновления не прерывали ввод и звук.
   Исправлено смещение пагинации после сохранения эталона в pending-списке.
4. Добавлен наблюдательный расширенный blacklist: 17 целых фраз первого коммита,
   без поиска по подстроке. Он только сохраняет предложение в
   `data.text_filter_shadow`; активный фильтр не заменяет.
   В UI есть «Перевірка фільтра», причина отметки и счётчики по пользовательским меткам.
5. Сохранены воспроизводимые снимки, результаты опытов и подробные отчёты.
   Модели не дообучались; рабочая модель, prompt и температурный fallback
   по результатам опытов пока не переключались.
6. По прямому уточнению пользователя 4 телефонных объявления о тревоге и
   один комнатный разговор перенесены из speech в room, с сохранением WAV
   и исходной расшифровки. Одна роль «ліра 63» исправлена с адресата на
   отправителя. Изменения ревизионные, журнал лежит в локальных отчётах.
7. Пользователь сам добавил в рабочий словарь «вулкан» и «ліра: 63».
   Эти данные живут в локальной SQLite, а не в конфигурации Git.

Разметка хранится в `.local-recordings/index.sqlite3`, WAV — рядом по ID.
`data` содержит исходный/итоговый текст, предложенный Qwen текст и решение,
сегменты Whisper, сигнал, время, настройки и прочие диагностические поля.
Для аналитики используй read-only SQLite и замороженные снимки.

веса моделей и не активируют словесные правила.

## Результаты проверок

### История проекта

Первый коммит — `7be59e0`, текущая база этой работы — `e4099de`.
Основной метод транскрипции, модель, параметры PCM и базовая VAD-нарезка
не изменились принципиально. На 48 WAV старая и новая нарезка совпали побайтово.
Это не доказывает одинаковые старые аудиоисточник/словари, которых Git не хранит.
Откат всего проекта не обоснован. Раньше вывод был чище из-за более широкого
blacklist, а Qwen и целофразное обучение были менее ограничены.

### Фильтрация

На новом корпусе расширенное совпадение целых фраз после текущего short_garbage
уменьшает оставшиеся ложные тексты с 73 до 51. Дополнительных потерь speech
на этом наборе нет, но есть одно дополнительное срабатывание на unclear.
Это офлайн-проверка выходов ASR, не частота ошибок на час и не число уведомлений.
В размеченных WAV ещё нет сохранённых полей нового shadow-наблюдения.

Старый поиск по подстроке дополнительно убрал бы настоящую радиозапись,
поскольку Whisper написал «Дякую, шторм…» вместо переданной фразы.
«Дякую» само может быть настоящим ответом. Не включай старый список по подстроке.
В комнатной записи распознано настоящее словарное имя «сапсан»: текстовым
blacklist это надёжно не отделить от радио. Отдельный аудиовход следует
проверить, если захват идёт через микрофон.

### Исправления Qwen

Большинство ошибок уже находится в исходном Whisper. В последней партии
нынешний guard не принял ни одного из 11 предложений, меняющих текст.
Более свободный guard с защитой словарей, чисел и количества слов принял бы
5 изменений, одно полезное: «отриму» → «отримав». Выигрыш — одно слово.
Это аргумент для адресного контекстного исправления, а не снятия всех ограничений.

Из правок получены кандидаты «отриму → отримав» (2 примера),
«прийома → прийом», «приєм → прийом», «послідку → посилку» (по одному).
Наивное обучение извлекает также «буря → прибой» и «я → ліра»;
действующая проверка исключает эти опасные замены. В базе 10 pending-правил,
активных на момент снимка нет. Ни одно новое правило в этой работе не активировано.

### Пустые ответы и температура

У всех 16 speech с пустым raw_text сохранены повторы с compression_ratio>2,4
и конечной температурой 0,4. Просто пропустить повторы нельзя: у пяти новых
таких записей число ошибок выросло бы с 48 до 298.

Выполнено свежее парное сравнение на 30 WAV: все 21 радиофраза последней партии
и по 3 noise/notification/room. Одни веса, снимок словарей с «вулкан», язык uk,
нормализация, seed 345, чередование AB/BA, предварительно загруженная модель:

| Метрика | Fallback 0/0,2/0,4 | Только temperature=0 |
|---|---:|---:|
| Ошибки / 132 слова | 133 | 131 |
| WER | 100,8% | 99,2% |
| CER | 78,1% | 73,5% |
| Правильные целые фразы | 0/21 | 0/21 |
| Речь без текста | 7/21 | 4/21 |
| Совпавшие группы цифр | 4/20 | 7/20 |
| Ложный raw_text на 9 отрицательных WAV | 7/9 | 7/9 |

| Медиана времени Whisper на Mac | 2,22 с | 1,01 с |

По числу ошибок 5 фраз лучше, 2 хуже, 14 одинаковы. Один из «успехов» WER —
замена длинного неправильного ответа пустым; не выдавай это за восстановление речи.
Время не изолировано от других служб и не переносится на Pi. Исторический
WER 95,5% этих ID нельзя напрямую сравнивать со свежим fallback как эффект
одного параметра: в свежем опыте текущий prompt и фиксирован seed.
Temperature=0 перспективна, но рабочий fallback не переключался.

### Более ранние опыты

На 88 общих WAV, включая 33 speech / 323 слова:
базовый Turbo WER 87,6%; без prompt 97,8%; полоса 300–3400 Гц 85,8%;
автоопределение языка 82,0%. У полосы ухудшился результат на малой
holdout-части; отмена prompt увеличила пропуски. Это исследовательские результаты.

На фиксированных 48 WAV, включая те же 33 speech, полная multilingual large-v3
дала WER 76,8% против 87,6% Turbo, 3 точные фразы вместо 0, пустые 2 вместо 12.
Медиана на Mac 5,06 с вместо 1,25 с. Полная модель улучшает некоторые случаи,
но качество остаётся слабым, шум не решён, скорость для Pi не доказана.
Готовой победившей конфигурации нет. Облачное распознавание обсуждалось,
но на этом корпусе не запускалось.

## Шаблоны: подтверждённые факты

Полную спецификацию смотри в ASR_TEMPLATES.md.

Полный протокол: `К, К, я О, ТЕКСТ, прийом`.
Допустимы один адресат, отсутствие адресата, отсутствие «я О», собственный
позывной без «я», отсутствие «прийом» и сочетания пропусков.
«П, прийнято, прийом» может называть любую из двух ролей. Не выводи роль
по этому шаблону как обязательное условие правильного распознавания.

Подтверждены семейства:
перевірка зв’язку; на зв’язок / на зв’язку; чую / розбираю;
до роботи приступив; роботу закінчив; посилку отримав;
прийнято / прийняв; цифровые группы; повторіть, голос не пройшов.
Редкие в корпусе «Прийняв, прийом» и просьба повторить подтверждены оператором
как реальные конструкции. В последней партии 20/21 speech содержат
«посилку отримав» либо «прийнято … прийом».

Пока точный нормализованный оборот «посилку отримав» отсутствует в сохранённом
raw/final всех 11 соответствующих WAV; «прийнято прийом» — всех 33;
«перевірка звязку» — всех 5. Это строгий поиск непрерывного оборота,
а не оценка всех близких форм. Разметка подтверждает повторяемость,
но текущая модель не использует её достаточно хорошо.

## Следующая задача: сначала проверить пользу шаблонов для ASR

1. Прочитай ASR_TEMPLATES.md, core/recognition.py, core/correction.py,
   core/audio.py, tools/asr_lab.py и локальные отчёты.
2. Подготовь короткий контекст из реальных оборотов без конкретных номеров
   проверяемых фраз. Сравни на фиксированных WAV три prompt:
   существующий словарь; только речевые обороты; словарь плюс обороты.
   Начни с одного и того же декодирования. Температуру, язык, модель,
   нормализацию и нарезку не меняй одновременно с prompt.
3. Сохрани ID, эталоны, хеши PCM/весов/словаря, полный prompt, параметры,
   версии, seed и результат каждого запуска. Результаты должны быть парными,
   без ошибок инференса; нулевой exit code сам по себе этого не доказывает.
4. Главные метрики: WER/CER, точные фразы, независимые группы цифр,
   пропуски, повторы, ложный текст на отрицательных WAV, задержка и RTF.
   Добавь точность характерных оборотов. Не оптимизируй сейчас роли.
5. Шаблоны мягкие: сохраняй открытую ветвь для новых сообщений и пропуски
   говорящих. Не генерируй недостающий заголовок/конец, не исправляй число
   по ожиданию, не отбрасывай вне-шаблонную речь. Подтверждай изменения аудио.
6. Если prompt помогает, проверь мягкую грамматику/выбор между акустическими
   гипотезами на поддерживаемом движке. Не заменяй это ближайшим шаблоном
   к одному испорченному тексту. Отдельно проверь сегментацию объединённых WAV.
7. Подбор выполняй на известных данных, финальную оценку — на новом сеансе.
   Не разделяй близкие повторы одного вызова по обучению и тесту.
   Если дойдём до LoRA/дообучения, обучай аудио→точный текст; аудиоархив
   сам веса не обучает. Цель первого расширения корпуса — около часа
   разнообразной проверенной речи, это ориентир, не гарантия качества.
8. Для переноса на Pi отдельно сравни компактные модели и движки. Любой
   результат на Mac — только качество/исследовательская скорость, не обещание Pi.

Не запускай второй рабочий приёмник и не перезапускай службы для офлайн-опыта.
Сначала подготовь сравнение и отчёт; рабочую конфигурацию меняй после
подтверждённого выигрыша. Не возвращай старое целофразное fuzzy-обучение,
меняющее номера, и не снимай проверки словарных имён ради красивого текста.
Не удаляй пользовательскую разметку и локальные результаты.
