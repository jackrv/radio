# Локальне керування, ролі й синхронізація Telegram

## Зміни

| Ділянка | Результат | Основні файли |
| --- | --- | --- |
| Чат бота | Відомі приватні команди видаляються; одна службова картка користувача оновлюється, заявки після рішення прибираються в усіх адміністраторів | `telegram_access.py`, `telegram_maintenance.py`, `telegram_updates.py` |
| Правки | Атомарна черга, ревізії, оновлення всіх відомих копій голосових і тексту, позначка оператора | `telegram_sync.py`, `miniapp_correction_editor.py`, `telegram_outbox.py` |
| Навчання | Незмінний початковий текст навіть у давніх подій без `raw_text`; повторні правки зберігають один голос джерела | `event_store.py` |
| Статистика | Окремо виправлені фрази, усі й активні правила; повторне редагування не збільшує число джерел | `miniapp_management.py`, `miniapp/management.js` |
| Сповіщення | Типово `commands` для editor/viewer; адміністратор задає режим разом із роллю, чинний `off` сам не скидається | `user_notify_store.py`, `miniapp_management.py`, `api/management.py` |
| Доступ | Viewer — тільки мінімальний стан. Editor — журнал, аудіо, правки, словники й особисті сповіщення; без користувачів, параметрів розпізнавання та паузи | `user_store.py`, `api/app.py`, `miniapp/` |
| Локальна панель | Налаштування, числові метрики, зразки WAV та перегляд ролей із серверною забороною запису | `api/local_dashboard.py`, `local_admin/`, `start_radio345.py` |
| Звуки | Приватне додавання, перевірка й видалення зразків; додавання чистого звуку з Mini App адміністратором; захист від безперервного тихого звуку на краях | `notification_samples.py`, `notification_filter.py`, `api/management.py` |

`telegram_maintenance` — один легкий потік мережевого обслуговування. Потоки
Whisper/Qwen, моделі, VAD і `MIN_RMS` не змінюються. Незавершені правки живуть у
SQLite, не в пам’яті цього потоку. Зовнішні запити виконуються після commit.

## Запуск після перевірки змін

```bash
.venv/bin/python start_radio345.py --local-admin
```

Або окремо, коли приймач уже працює:

```bash
.venv/bin/python -m api.local_dashboard
open "$(cat .radio345-local-admin/access-url.txt)"
```

Останню команду виконуйте лише у своєму локальному терміналі. Не вставляйте її
результат із ключем у чат, скриншот або issue. Ключ у фрагменті URL передається
тільки локальному входу; скрипт прибирає його з адресного рядка. Далі працює
HttpOnly/SameSite=Strict cookie. Панель перевіряє loopback, Host, Origin записів
і локальну сесію. Ключ змінюється при перезапуску; строк cookie — 12 годин.
Порт 8766 не слід публікувати через ngrok чи перенаправлення портів.

Вбудований запускатель керує панеллю за тим самим механізмом життєвого циклу:
спершу завершує radio і Telegram, потім панель, ngrok та API. Робоча база не
очищується, файл `.radio345.lock` не видаляється. Міграції додають таблиці,
не видаляючи наявних даних.

## Ручна перевірка на Mac і Telegram

1. Перед оновленням дочекайтесь завершення нічного вимірювання і збережіть
   `diagnostics.json`. Завершіть запускатель штатно; нічний процес не переривався
   під час розробки цих змін.
2. Після погодженої публікації дочекайтесь успішного GitHub Pages workflow.
   Він копіює всі скрипти Mini App; локальні файли панелі до Pages не входять.
3. Запустіть із `--local-admin`, відкрийте приватне локальне посилання. Перевірте
   статистику, давність знімка, mean/p95/max і чергу правок Telegram.
4. Перегляньте `viewer`, `editor`, `admin`. Viewer має бачити лише стан; editor —
   робочі розділи без адміністративних прав. Спроба зберегти будь-що в перегляді
   повинна закінчитись відмовою, фактичні ролі не змінюються.
5. У справжньому Mini App адміністратором задайте тестовому editor режим `off`,
   потім `commands`. Список має відображати збережений вибір. Неможливо надати
   `all` неадміністратору або вимкнути останнього адміністратора.
6. У боті надішліть `/start`, `/off`, `/commands`: власні команди прибираються,
   відповідь оновлюється в одній картці. Звичайний текст не видаляється.
   Перевірте запит нового користувача: очікування замінюється результатом,
   картки підтвердження адміністраторів зникають після рішення.
7. Доставте одну нову фразу двом користувачам. Виправте її редактором: обидві
   копії мають отримати новий текст і позначку. Перевірте також резервний текст,
   повторне редагування та відсутність додаткового голосу від того самого джерела.
8. Збережіть правку при недоступному Telegram, потім відновіть мережу: черга
   переживає перезапуск. Прострочена `mem:` або прихована фраза не відновлюється.
9. Додайте тільки чистий WAV сповіщення (PCM16/mono/16000 Гц, до 5 с, сам сигнал
   0,04–2 с). Перед підтвердженням обов’язково прослухайте його. Перевірте збіг
   записом із тихими краями, потім сумішшю з мовленням: суміш має пройти далі.
   Зразки до 16 файлів, приватні, права 0600. Видалення/додавання діє після
   перезапуску приймача; це не навчання ваг Whisper.
10. `Ctrl+C`, `--status`, `--stop`: керовані процеси й порти звільняються. Окремо
    запущена адмінпанель має свій Ctrl+C.

## Обмеження

- Бот не може отримати всю історію чатів. Старі копії без `message_id` і старий
  службовий смітник не видаляються й не оновлюються заднім числом. Відомі давні
  посилання мігрують; усі нові копії реєструються по отримувачах.
- При тайм-ауті надсилання Telegram міг прийняти голосове без повернення його ID.
  Таку невідому копію не можна оновити. Повтори **sendVoice не змінені**.
- Синхронізація правок асинхронна, звичайно після чергового 5-секундного циклу,
  довше за мережевих збоїв і великої черги. До 5 копій за цикл. Враховується
  `retry_after`, до 8 невдалих спроб правки; нова правка джерела відновлює спроби.
  Недоступні для редагування або видалені повідомлення не створюються заново.
- Дуже довгий текст підпису Telegram обрізається до 1024 UTF-16 одиниць, резервний
  текст — до 4096; повна правка залишається в SQLite. Позивні й числові групи
  автоматично не перефразовуються.
- Лічильник давніх виправлень відновлюється з джерел голосів. Давні правки без
  жодного словесного голосу й без історії обліку відновити неможливо. Нові правки
  рахуються незалежно від придатності до словесного навчання.
- Зіставлення сповіщень консервативне. Інший звук, акустика чи гучний фон можуть
  не збігтися. Дуже тихе мовлення нижче фонового шуму неможливо гарантувати
  виявити; сумнівні сегменти залишаються для Whisper. Потрібна перевірка власним
  мікрофоном і телефонами, а не лише синтетичні тести.
- Перегляд ролей використовує справжні дані з правами вибраної ролі, але не
  відтворює поведінку мобільної клавіатури Telegram і не замінює перевірку
  окремими обліковими записами. Мобільний вигляд перевіряється вручну.

## Автоматичні перевірки

```bash
.venv/bin/python -m pytest -q -p no:cacheprovider
node --test tests/miniapp.test.cjs
node --check local_admin/admin.js
git diff --check
```

Тести використовують тимчасові бази, синтетичні WAV і підмінений Telegram.
Якщо ffmpeg встановлений, окремо перевіряється реальний цикл OGG → PCM WAV.
Реальні моделі й аудіопристрій у цих тестах не запускаються. Зовнішню доставку
Telegram і поведінку справжнього телефона цим прогоном не підтверджено.

Перевірено 2026-11-15:

- Повний Python-прогін у чистій копії кінцевих вихідних файлів: **748 passed**.
- JavaScript Mini App: **37 passed**.
- `node --check local_admin/admin.js`, `git diff --check`, перевірка зайвих імпортів
  через AST і кінцевих пробілів — без помилок.
- Чиста копія не містила `.env`, `events.db`, приватного списку побажань або
  робочих аудіозаписів. Перетворення синтетичного OGG реальним ffmpeg пройшло.
- Нічний приймач, робоча SQLite і зразки телефона під час розробки не змінювались.
  Реальний Telegram, мобільний WebView і точність на справжніх сповіщеннях
  потребують описаної вище ручної перевірки. Commit/push не виконувались.
