## Автоматичні копії

Працюючий приймач раз на добу (перша — через 5 хв після старту) створює
`.local-backups/events-auto-<час UTC>.db`: SQLite Backup API, `integrity_check`,
звірка кількості рядків, права 0600. Зберігаються останні 7. Збій пишеться в
журнал і `backup.failed`, але не зупиняє приймання. Копія вручну — «Система →
Створити зараз».

## Відновлення

### Аудіокорпус окремо від подій

Копія `events.db` **не містить** WAV та індексу аудіоархіву. Повна копія корпусу:
**Система → Резервна копія аудіокорпусу**. Це фонове завдання з manifest,
контрольними сумами SHA-256 та перевіркою SQLite. Неповна копія не стає успішною;
якщо pruning випередив копіювання WAV, потрібно повторити операцію.
Автоматичне створення та ротацію таких копій не ввімкнено. На тому самому диску
копія допомагає після випадкового видалення чи пошкодження; для відмови диска
потрібен окремий носій. Копії приватні й не потрапляють до Git.

```bash
.venv/bin/python -m tools.archive_backup backup
.venv/bin/python -m tools.archive_backup verify .local-archive-backups/archive-<час>
.venv/bin/python -m tools.archive_backup restore .local-archive-backups/archive-<час> --destination .local-restored-archive
.venv/bin/python -m tools.archive_backup inventory
```

Restore створює **лише нову теку**; робочий архів не перезаписується. Перевірити копію
й відновлену теку слід до окремого рішення про заміну робочого корпусу.
«Звірити WAV з індексом» нічого не видаляє; файли без рядків індексу враховуються
лише старші години, щоб не плутати з поточною операцією запису.

### Основна база

Лише командою, не копіюванням файлу, і **при зупиненому лаунчері**:

```bash
.venv/bin/python manage_database.py restore --from .local-backups/events-auto-….db
```

Поточна база спершу зберігається як `events-before-restore-…`. Лічильник ID
подій і позиція опитування Telegram не опускаються нижче поточних — старі кнопки
не відкриють нових подій, старі команди не виконаються вдруге. Після
відновлення: `diagnose_radio345.py`, потім запуск.

## Експорт і новий початок

```bash
.venv/bin/python manage_database.py export                  # словники → dictionaries.txt
.venv/bin/python manage_database.py reset --confirm-reset   # очистити дані
```

`reset` робить перевірену копію й експорт словників, зберігає активних
адміністраторів (`--remove-admins` — ні), лічильники ID і offset Telegram.
Очищуються події, навчання, словники, профілі й налаштування. Аудіо, журнали й
старі повідомлення Telegram не видаляються. Для звичайної роботи видаляти базу
**не потрібно**.
