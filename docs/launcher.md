# ⚙️ Запуск і служби

[← Вікі](README.md)

`start_radio345.py` запускає й супроводжує чотири служби: **API** (127.0.0.1:8765),
**ngrok**, **приймач** (`radio.py`) і **локальну панель** (127.0.0.1:8766).

## Команди

| Команда | Дія |
| --- | --- |
| `start_radio345.py` | запустити все |
| `--status` | керований запуск, PID, порти, блокування приймача |
| `--restart` | перезапустити служби в тому ж вікні (код самого лаунчера — лише після повної зупинки) |
| `--stop` | зупинити все |
| `--receiver-stop` / `--receiver-start` | лише приймач; панель, API й Mini App працюють |
| `--no-local-admin` | без локальної панелі |
| `--local-miniapp` | локальний перегляд Mini App на 127.0.0.1:8080 |
| `--ngrok-url https://…` | постійний домен ngrok |
| `--publish-pages` | дозволити commit/push адреси API в `main` (інакше push немає) |

Ті самі кнопки є внизу меню панелі. Зупинка приймача окремо — для важких
офлайн-прогонів: модель звільняє пам’ять, а Mini App і панель доступні.

Лише приймач без лаунчера: `.venv/bin/python -u radio.py`.

## Як зупиняється

`Ctrl+C`, `SIGTERM`, `SIGHUP` чи `--stop`: спершу приймач (закриває мікрофон,
дочікується черги Telegram до 10 с, усього до 30 с), потім панель, ngrok і API
(по 5 с). Кожна служба має легкий контролер без MLX: якщо лаунчер зник, контролер
сам зупиняє службу в тому ж порядку. `--stop` діє лише на власний запуск через
приватний канал із токеном — чужі процеси не шукаються й не вбиваються.

Другий приймач не запуститься: `radio.py` тримає `flock` на `.radio345.lock`.
**Не видаляйте цей файл** — ОС сама знімає блокування, коли процес завершується.
Перевірити зайняті порти: `lsof -nP -iTCP:8765 -sTCP:LISTEN` (так само 4040, 8766).

## Самовідновлення

- **Сон Mac.** Закрита кришка зупиняє приймання. Після пробудження приймач
  відновлюється сам і надсилає адміністраторам «Приймання ефіру було перерване»
  з часом розриву. Для безперервної роботи кришку тримайте відкритою.
- **Мікрофон** без звуку 10 с перевідкривається автоматично.
- **Розпізнавання** понад 3 хв на сегмент або 5 помилок Whisper поспіль —
  критичний запис у журнал і повідомлення «Розпізнавання не відповідає»;
  після відновлення — «знову працює». Завислу модель вирішує лише перезапуск.
- **ngrok**: короткий обрив показується як «тунель перепідключається…».

## Консоль

Компактна панель у окремому екрані термінала: кольорова плашка стану, час роботи,
фрази, черги, втрати, затримки (середня й p95), стан Whisper, посилання на
панель і останні 8 подій. Стани: **ЗАПУСК**, **ПРИЙМАННЯ**, **ПАУЗА**,
**НЕМАЄ ЗВ’ЯЗКУ** (heartbeat застарів), **ПОМИЛКА ДІАГНОСТИКИ**, **ЗУПИНЕНО**.
Посилання на панель у macOS Terminal відкривається **⌘ + подвійним кліком**.
Якщо запуск не вдався, причина лишається в терміналі червоним.

## Журнали

| Файл | Що |
| --- | --- |
| `radio.log` | повний журнал приймача з traceback |
| `launcher.log` | вивід усіх служб (5 МБ × 5 архівів) |

Токен Telegram маскується. Журнали містять тексти ефіру — вони приватні.
`RADIO_DEBUG_AUDIO=1` вмикає обмежений запис зразків у `debug_audio/` (теж приватний).
