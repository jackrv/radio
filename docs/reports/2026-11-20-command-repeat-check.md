# Повтор коду команди: словник, прототип і контроль

[← Звіти](README.md)

Дата **20.11.2026**, commit `3f7f8b8b30ae3aa2ea1e67b54824d3edede2de65` із
незакоміченою попередньою роботою. Коміт/push не виконувалися; живі словники не змінювалися.

**Оновлений стан після уточнення власника:** він вимагає повного вигляду впізнаного
блоку команди за словником. Відновлення однозначного повтору ABAB **увімкнено**
за замовчуванням в остаточному оформленні та редакторі; `raw_text` і позначка
«почуто одну пару» зберігаються. Інші цифри не підміняються, захист неоднозначності
залишено. Наведене нижче очікування рішення — історичний проміжний стан.
Спостережені 6 покращень/8 погіршень загальної перевірки залишаються обмеженням,
увімкнення не слід подавати як доведене загальне покращення ASR.

Власник попросив відновлювати пропущену повторну пару цифр, використовуючи словник,
й уточнив формат рядків. Синтетично підтверджено: `злива 4242` та `злива 42 42`
без двокрапки означають один код `4242`; `злива: 42 42` означає дозволений номер `42`.
Заміна одного формату іншим не усуває пропуск у виході Whisper.

## Реалізація та поточне рішення

`core/command_completion.py` шукає точну назву команди + одну двозначну групу AB,
якщо словник однозначно дозволяє ABAB. Не спрацьовує за іншими числами, наступною
числовою групою, коротким дозволеним кодом, іншим словниковим продовженням,
колізією позивного, вбудованим ідентифікатором, датою/дробом/цитатою.
Використовується чинний словник, без нового переліку робочих назв у коді.

Автоматичний прототип перевірено через явне `tidy_text(..., restore_codes=True)`.
Після контролю **типове значення залишено False**; живий потік не дописує цифри.
Редактор натомість дає явну підказку з окремою кнопкою й поясненням перевірити на слух.
Це `info`, не автоматична правка написання або «Виправити оформлення»;
помилкове повідомлення «додайте цей номер у словник» для такого випадку прибрано.
Первинний Whisper і позначка «почуто одну пару» в заголовку зберігаються.

## Контроль на збережених даних

SQLite snapshots відкритих лише на читання джерел: **2114 записів**, із них
**998 мовлення / 1116 негативних**. Порівнювався один і той самий текстовий pipeline
із вимкненим/увімкненим лише цим відновленням, а не нове розпізнавання аудіо.

- Змінено 20 мовленнєвих записів: **6 краще, 8 гірше, 6 без зміни кількості помилок**.
- «Без правок» **106 → 106**, словесних помилок **4609 → 4607**,
  пропуски **35 → 35**, хибний текст **525 → 525**.
- Це порівняння з розміткою, не прослуховування. Вісім розбіжностей потребують
  окремої перевірки: словник сам по собі не доводить, що в конкретному аудіо є повтор.
- Власникові повідомлено результати й запитано вибір: поки явна підказка з
  перевіркою восьми випадків або свідоме автоматичне відновлення. **Відповідь очікується**;
  без неї прототип не вмикати за замовчуванням.

Повний прогін прототипу: **1316 Python passed / 126 Node passed**.
Після вимкнення default та переведення редакторної дії в явну підказку:
**70 адресних Python-тестів passed**, `git diff --check` пройшов.
Моделі, VAD/RMS, база, аудіо й запущені служби не змінювалися перевіркою.

## Уточнення за запитом власника: показати конкретні записи

Повторний пошук саме названої власником команди з однією парою у **raw_text**
знайшов **2 мовленнєві записи**. В обох еталон підтверджує повтор; кожен виграє
одну словесну помилку після відновлення. **Ухудшень для цієї конкретної команди
в перевіреному наборі немає.** Число «8 гірше» стосується всіх інших команд разом,
не можна подавати його як доказ проти конкретного прикладу власника.

Серед загальних погіршень є вже хибно впізнане слово-команда замість позивного:
відновлення повтору посилює вихідну помилку ASR. Це інший механізм, а не доказ,
що в правильно визначеної команди справді вимовлялася лише одна пара.
Не виконували прослуховування й не стверджуємо, що операторський еталон безпомилковий.

Обидва формати словника перевіряються також через EventProcessor: однаковий
підсумковий текст, незмінний raw і збережена помітка часткового виходу Whisper.
Після ввімкнення: повний прогін **1316 Python / 126 Node passed**;
після додавання ще одного параметра інтеграційного тесту обох словникових форматів —
**22 адресні Python-тести passed**. `git diff --check` пройшов.

## Знайдена невідповідність валідатора збереження

Власник повідомив, що панель відхиляє пробіли повідомленням про діапазони.
Попередні перевірки підтверджували парсер, але не повний шлях запису цієї форми
через API; загальне твердження про готовність збереження було передчасним.
Причина: `services/management/dictionaries.py` вимагав одну суцільну цифрову
групу без двокрапки, хоча parser уже розумів розділений код.

Виправлено саме словник `commands`: без двокрапки числові групи означають один
код (не діапазон/список), до 9 цифр сумарно. Вихідний `raw_line` з пробілами
зберігається як є; склеювання є лише ключем порівняння, не формою відображення
або вимовою числа. Для позивних і списків номерів правила не послаблювалися.

Нові API-регресії виконують перевірку чернетки → збереження → повторне читання
→ завантаження розпізнавачем, включно з початковим нулем (`грім 0 22`).
Окремо відхиляються надмірно довгі коди, діапазони й wildcard без двокрапки.
Адресний прогін **86 passed**; повний прогін **1324 Python passed**, `git diff --check` пройшов.
Живий словник не змінювався; для нового валідатора потрібен перезапуск процесу панелі.
