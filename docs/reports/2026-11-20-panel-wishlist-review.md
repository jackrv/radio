## Що зі списку не слід вважати новим або доведено завершеним

- Аліаси працюють; порожній список не є дефектом. Неперевірені кандидатні заміни
  в живі дані не додавалися, механізм не видалено. Кандидати й пояснення доступні в довідці/інструментах.
- Навчання архіву, історія «Готово», проба вимкнення правила перед збереженням,
  автоочищення Telegram, структурована активність і ручна копія корпусу реалізовані
  на попередніх етапах; відповідні backend-регресії залишилися в повному прогоні.
  Реальне масове навчання/копіювання/видалення Telegram зараз не запускалося.
- Старі події активності не отримують вигаданої деталізації. Порожня тимчасова БД
  не доводить зручності кожного можливого реального стану або історичного запису.
- Capture-only захищає прийом аудіо під час тестів, але не робить часові вікна тесту
  безмежними й не прискорює ASR. Важкі тести й новий приймач тут не запускалися.
- Контекстне дослідження «прийнято, прийом» залишається відкладеним за рішенням власника.
  Інші цифри не підміняються. Попередні докази змішаного ефекту відновлення ABAB
  та дослідження причини SQLite/SIGBUS не скасовані версткою.

## Перевірка

- Ізольований Chrome/API/профіль із синтетичними SQLite та WAV: **45 станів** —
  всі групи/вкладки при ширинах **1440, 1100, 760 px**. Переповнення сторінки по
  горизонталі **0**, помилок JavaScript **0**; настільні знімки переглянуто.
- Окремий сценарій через DOM: пошук → точна вибірка → архів, маркер/пауза/перемотка,
  редагування тексту й швидкість, словник → додати рядок → ввімкнути → зберегти
  команду з пробілами → перевірити запис API, чернетка коду → інша вкладка → повернення,
  чип після збереження, згортання меню, системне налаштування й навігація людей.
  На окремих синтетичних голосах навчання перевірено пошук і явний дозвіл заміни через UI.
- Цей сценарій збережено: **`node tools/check_panel_ui.cjs`**. Потрібні `.venv`,
  Node із WebSocket та Chrome; інший шлях браузера — `CHROME_BIN`.
  Fixture `tests/panel_browser_fixture.py` створює тільки синтетичні дані в тимчасовому
  каталозі, сервер прив'язаний до випадкового loopback-порту. Тест не використовує
  робочий браузер/базу/аудіо та зупиняє лише власні процеси. Знімки залишаються
  в надрукованому тимчасовому каталозі для огляду.
- Нові Node-регресії: чернетки за датою, введення під час збереження, видалення чипа,
  перегонка двох пошукових відповідей, старий збій після нового успіху та порядок архіву.
- Чиста копія без `.env`, робочої БД, словників/аудіо/приватних каталогів:
  **1324 Python / 131 Node passed** (спільне встановлене `.venv`, не чиста інсталяція пакетів).
  Після останньої очистки ресурсів плеєра повний Node-прогін **132 passed**, включно
  з новою регресією зупинки старого аудіо; Python після суто JS-зміни не повторювався.
  Синтаксис JS і `git diff --check` пройшли. Реальні MLX/Telegram/iOS не перевірені.

## Перевірка власником

Для всього незакоміченого набору, включно з попереднім виправленням серверного
валідатора, перезапустити лаунчер й оновити сторінку панелі. Потім перевірити
власні довгі списки, запис із багатьма словами, перехід між датами кодів,
збереження команд і реальну чергу експериментів. Візуальну оцінку власника не
підміняє факт відсутності overflow; зауваження до конкретного екрану залишаються
підставою наступної правки.

Знімки основних синтетичних екранів для локального порівняння:
`.local-experiments/panel-review-2026-11-20/{codes,experiments,archive}.png`.
У Git не включаються; для нового знімка запускається збережений smoke-тест.

Уточнення за скріншотом власника: після збереження кодів прибрано дублюючий
рядок успіху з датою/кодами. Достатньо оновлених плашок; помилки збереження
залишаються видимими. Застосовано до постійних кодів і кодів доби.

За наступним скріншотом власника прибрано окремі дубльовані плитки проблемних
служб під health-line. Причина була в навмисному renderServices(problems), а не
переповненні рядка. Стан, причина проблеми й перехід до діагностики лишаються
в health-line; 135 Node-тестів passed, git diff --check пройшов.
