# Налаштування локального claudeSearch

21.11.2026. Перевірений HEAD `dbf832f69dfb4d6377efca5c78c24e3e322fc3a1`,
main, дерево містить попередні незакомічені зміни. Власник доручив установити
вже наявну папку claudeSearch та налаштувати її для Radio 345.

## Зроблено

- Через Homebrew встановлено PHP CLI 8.5.12 з PDO SQLite та його залежностями.
  PHP-FPM/Apache як служби не запускали; приймач і панель не перезапускали.
- `claudeSearch/config.php`: корінь репозиторію, окремий індекс
  `claudeSearch/code_graph.sqlite`; JS-граф для local_admin, miniapp, tools,
  tests з розширеннями js/cjs/mjs. Текстовий пошук охоплює також Python,
  HTML/CSS, документацію, конфігурації й публічні шаблони з кореня без
  повторного обходу вкладених каталогів.
- Поточна робоча БД — SQLite `events.db`. Вбудовані команди `schema`/`db`
  підтримують лише MySQL: для цього проєкту вони явно завершуються з кодом 2
  і поясненням, без підключення до робочої БД. PHP-розбір `route` так само
  вимкнений: FastAPI-маршрути шукати через `raw`/`usages`.
- У `claudeSearch.php` розширення SQL-пошуку беруться з `$sqlExtensions`;
  у нашій конфігурації py/sql. Попередній fallback php/go збережено.
- `.claudeignore` виключає середовища, кеші, приватні `.local-*`, секрети,
  робочий словник, БД, логи й аудіо. Це необхідно: інструмент навмисно
  **не читає `.gitignore`**. Сам claudeSearch виключений із пошуку коду проєкту.
- У кореневий `.gitignore` явно додано індекс та його SQLite sidecars.
  Embeddings не налаштовані: зовнішнім провайдерам код не передається.

## Використання з кореня репозиторію

```bash
php claudeSearch/buildGraph.php
bash claudeSearch/cs.sh raw TelegramService
bash claudeSearch/cs.sh usages openRecordings
bash claudeSearch/cs.sh sql radio_events
bash claudeSearch/cs.sh graph files openRecordings
```

Python-парсера в наданій версії **немає**. Пошук `.py` текстовий;
граф не є графом Python-залежностей. JS-парсер використовує регулярні вирази,
тому його символи/зв'язки — навігаційні підказки, не точний AST і не доказ
того, що код використовується або не використовується. Автоматичний пошук
не є sandbox: явні файлові команди стороннього CLI не слід застосовувати
до приватних даних. Нових дозволів агентам у `.claude/settings.json` не додавали.

## Перевірки й обмеження

- PHP lint конфігурації та CLI, `bash -n` обгортки — успішно.
- Повна побудова: **41 JS/CJS файл**, 2346 записів символів, 9744 зв'язки.
  Це кількість рядків індексу regex-парсера, не число функцій Radio 345.
- Повторна побудова: updated 0 / skipped 41; integrity_check індексу — ok.
- Реальні smoke-команди: Python raw, SQL у Python, JS graph files — успішно.
- db/schema/route повертають код 2 з поясненням.
- Перевірено правила ignore для приватних шляхів і доступність публічних
  шаблонів. Додатковий тимчасовий синтетичний `.local-*` файл із маркером
  справжній рекурсивний raw-пошук не знайшов; файл видалено після перевірки.
- `git check-ignore` підтвердив індекс/WAL/SHM; `git diff --check` пройшов.
  Повний Python/Node набір не запускався: робочий застосунок не змінювався.

Живі БД, аудіо, налаштування розпізнавання не змінювали.
Commit/push не виконували. Окреме розширення Python AST чи підтримка SQLite
команд schema/db у сторонньому інструменті до цього завдання не входили.

## Доповнення 22.11.2026: Python-парсер

За дорученням власника додано `claudeSearch/parsers/python.php` (регулярні вирази + стек
відступів, не AST) і підключено в buildGraph/config (`'py' => [$rootDir]`, ignore — `.claudeignore`).
Символи: класи, методи `Class::m`, функції й вкладені `outer.inner`, константи UPPER_CASE,
FastAPI-маршрути (`route`, `GET /path`); зв'язки: import, call, instantiate, extends, decorator.
Рядки/docstring/коментарі вирізаються. `method`/`block` і `outline` для `.py` — за відступами;
`graph callers` тепер враховує також instantiate.

Перевірки: `php -l` усіх змінених файлів; синтетичний приклад (docstring з def, рядок із
викликом, багаторядковий імпорт, вкладена функція, багаторядковий декоратор маршруту) —
усі символи/зв'язки правильні. Реальна побудова: 305 .py за ~0,5 с; 144 класи, 377 методів,
2354 функції, 387 констант, 106 маршрутів, 23239 зв'язків; файлів із `.venv`/прихованих
каталогів у графі немає. Обмеження: динамічні виклики, `getattr`, присвоєні функції
та ідентичні імена в різних модулях не розрізняються. Робочі БД/служби не змінювали.
