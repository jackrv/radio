# Година для тихих записів low_rms

[← Звіти](README.md) · 21.11.2026 · HEAD `dbf832f`, dirty

**Рішення власника.** `RECORDINGS_LOW_RMS_RETENTION_SECONDS = 3600`: лише **нерозмічене status=low_rms**, незалежно від
довжини, від `created` (початкового `captured_at`); повторна обробка чи відкладене збереження годину не поновлюють.
Захищено: розмітка (і порожній еталон шуму), `deferred` до розпізнавання (далі — строк нового статусу).
Решта нерозміченого — 7 днів / 5 GiB; обмеження обсягу може прибрати раніше. Короткі розпізнані відповіді за довжиною
не відсіюються. VAD/RMS і моделі не змінено.

**Устрій.** Ротація й прогноз сховища беруть один `prune_snapshot` (раніше прогноз вважав deferred незахищеним).
Рівно 3600 с — уже прострочення. Очищення — після save та в idle `recording-writer` (queue.get до 60 с, і в паузі):
фактично до хвилини пізніше; вимкнена служба не видаляє. Помилка idle — `recordings.prune_error` і нова спроба.
WAV видаляється після commit: збій commit не лишає рядка без аудіо, збій unlink може лишити файл-сироту
(видно в інвентарі; автоочищення немає). Старий сервер без нового поля UI не видає за годинну політику.

**Перевірено.** `tests/test_low_rms_retention.py` (межа години, розмітка, deferred, інші відсіви, збої, rollback;
прогноз збігається з видаленням) і Chrome-сценарій — на синтетиці.

**Не перевірено.** Година на приватному аудіо, ручна ротація живого архіву. Правило діє після штатного перезапуску
й поширюється на вже наявне нерозмічене low_rms.
