# Radio 345 Mini App

Панель на HTML, CSS и JavaScript без сборки и npm. Публикуется из `miniapp/`
workflow `.github/workflows/miniapp-pages.yml`. Данные остаются в локальной SQLite,
доступ к FastAPI идёт через настроенный HTTPS-туннель.

## Возможности

- Главная: heartbeat приёмника, количество событий, активных словесных правил
  и включённых строк словарей, время последнего события, Telegram ID оператора.
  Состояние Whisper, Qwen и доставка Telegram отдельно не диагностируются;
  панель не выдаёт heartbeat за подтверждение их работоспособности.
- Исправления: поиск по исходному и текущему тексту, страницы журнала событий
  и временных `mem:`-фраз, открытие существующего редактора. Временные фразы
  доступны 24 часа, максимум 200. Исправление и обучение слов атомарны;
  повторная правка одного источника заменяет его голоса. Автозакрытие сохраняется
  на устройстве; с выключенным чекбоксом можно продолжить правку.
  При выборе записи редактор переносится перед журналом: асинхронная загрузка
  списка не сдвигает поле. Клавиатура открывается при касании поля.
- Аудио: у новых голосовых сообщений сохраняется только связь с Telegram
  (`file_id`, chat/message ID). Кнопка рядом с фразой загружает OGG через
  авторизованный API и показывает плеер. Токен бота и `file_id` не выдаются
  браузеру; аудио не записывается в SQLite или на диск. Загрузка ограничена
  2 МБ, сетевыми таймаутами и сроком доступности фразы. Если устройство не
  поддерживает OGG, исходное голосовое можно прослушать в Telegram.
  Для старых сообщений, отправленных до сохранения связей, кнопки аудио нет;
  автоматически восстановить их по истории чата Bot API не позволяет.
- Удаление кнопкой бота: фраза скрывается из журнала исправлений и редактора,
  но само событие и существующие голоса обучения сохраняются. Работают и
  старые кнопки, если ID можно получить из их разметки или сохранённой связи.
  При недоступной SQLite удаление не начинается. Намерение удаления сохраняется
  до запроса Telegram; при явном отказе фраза остаётся видимой, при сетевой
  неопределённости скрывается до завершения повторной обработки. Обычное ручное
  удаление средствами Telegram не сообщает боту о событии и не синхронизируется.
  Удаления, сделанные до установки этой версии, задним числом не восстанавливаются.
- Словари: строки позывных, команд и списка наблюдения, включение/отключение,
  добавление и удаление строк. Проверяется формат номеров и диапазонов;
  нельзя оставить приёмник без позывных. Обновление применяется после
  перезапуска приёмника. Словарь сохраняется целиком с проверкой его версии.
- Обученные замены: поиск, число подтверждений, статус, отключение и повторное
  включение с обычной проверкой подтверждений и конфликтов. Голоса вручную
  не добавляются, проверки безопасности движка не обходятся.
- Настройки: режим уведомлений применяется сразу. Qwen, уровень VAD,
  тишина до конца фразы, минимальная речь и максимальная длина сегмента
  сохраняются в `recognition_settings` и применяются при следующем запуске
  `radio.py`. Форма показывает сохранённые, а не фактически активные значения.
- Пользователи: добавление по Telegram ID, изменение роли и отключение доступа.
  Последнего активного администратора отключить или понизить нельзя.

## Права

| Роль | Доступ |
| --- | --- |
| Наблюдатель | Состояние, сводка, журнал, просмотр словарей и правил |
| Редактор | Всё выше, исправления фраз, словарей и состояния правил |
| Администратор | Всё выше, настройки, пауза аудио и пользователи |

Каждый API-запрос проверяет подпись и срок Telegram `initData` и актуальные права
в SQLite. Роль на клиенте используется только для отображения кнопок.
Для операций управления версия и права повторно проверяются внутри SQLite-транзакции.
Данные API не кэшируются. Текст из базы вставляется через `textContent`/`value`.
Общий HTTP-клиент ограничивает ожидание 15 секундами; отмена запроса не гарантирует
отмену уже начавшейся серверной транзакции. При сомнении обновите данные перед
повторной правкой. Конфликт версии не перезаписывает чужие изменения.

## Проверка и публикация

```bash
venv/bin/python -m pytest -q
node --test tests/miniapp.test.cjs
```

Синтаксис каждого JS-файла можно проверить `node --check miniapp/<имя>.js`.
Тест `test_miniapp_assets.py` проверяет включение всех локальных ресурсов в Pages
workflow и порядок загрузки общего клиента. Node-тесты используют модель DOM;
они не заменяют проверку внешнего вида и поведения на настоящем устройстве.

Перед публикацией новой панели перезапустите API и приёмник, чтобы стали доступны
новые маршруты. `Ctrl+C` у запускателя, затем `venv/bin/python start_radio345.py`.
Не запускайте второй экземпляр приёмника параллельно первому.
Commit/push выполняются после согласования. Проверяйте результат workflow Pages.

В Telegram закройте старое окно и откройте Mini App заново:

1. Проверьте сводку, режим уведомлений и паузу под администратором.
2. Найдите фразу в журнале, исправьте её и повторно откройте. Повторите для
   кнопок `db:` и `mem:` под сообщениями, с включённым и выключенным автозакрытием.
3. Проверьте поиск украинского текста и переход между страницами.
4. Проверьте словари и правила сначала в режиме просмотра. На тестовых данных
   проверьте правку, отключение и конфликт двух сессий. Изменение словаря
   подействует после перезапуска приёмника.
5. Проверьте сохранение настроек и их применение после перезапуска на тестовой
   конфигурации. Не меняйте VAD рабочего эфира ради проверки формы.
6. Добавьте тестового наблюдателя/редактора, проверьте ограничения и отключение
   его доступа. Не отключайте единственного рабочего администратора.
7. При остановленном туннеле проверьте понятную ошибку и повторную загрузку.

Для локального просмотра можно использовать `--local-miniapp` запускателя.
Без Telegram-авторизации панель не получает данные; прямой доступ с localhost
к API ограничен существующей CORS-политикой. Секреты, SQLite и записи эфира
никогда не копируются в опубликованные ресурсы.
